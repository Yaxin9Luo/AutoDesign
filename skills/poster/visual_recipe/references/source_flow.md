# Source flow

Use selected and required `poster_plan_contract` source ids before prose-only panels. Primary assets are required; secondary assets fill available capacity; reserve assets replace failures; rejected or forbidden assets remain unused. Numeric claims must appear in source text, table, or caption.

Each source figure or table and its explanation is a local `.figure-flow-unit` or `.source-flow-unit`. Use browser-native flow, float, or shape-outside for the local readout and grid/flex for outer structure. Do not separate one asset from its explanation with unrelated lanes, use visible `figcaption` rows, or prefix visible readouts with original `Fig.` or `Table` labels. Preserve `data-source-id` and `data-layer-id`.

Make source assets primary rather than thumbnails. Use one wide asset sparingly per column and repair cramped side lanes with stacked/full-width flow. Keep list marker gutters readable beside floated assets. Never regenerate evidence to solve layout.
