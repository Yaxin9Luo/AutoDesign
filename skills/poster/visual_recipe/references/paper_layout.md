# Paper poster layout

Author complete editable HTML/CSS through `propose_paper_poster_html` for attached-paper posters. The contract is authoritative for content, selected visuals, panel plan, density, required sections, and acceptance tests; fix rejected HTML/CSS rather than falling back to legacy composite/finalize paths.

Default conference posters use a compact identity header and three editorial columns with one to three normal-flow sections each. Allocate the real section blocks across the available column height; do not leave blank bottom strips, reserve empty panels, use fixed full-canvas column heights below the header, or use hidden overflow to crop. Prefer visual/table/native structure over prose. Use the six-panel legacy board only when the contract explicitly requests it.

Repair capacity locally: shorten low-value readouts, tighten gaps and padding, make bounded asset adjustments, then remove only optional secondary assets. Density floors require visible, readable, non-overlapping content; never meet them with tiny text, hidden overflow, boilerplate, or chip/card repetition.
